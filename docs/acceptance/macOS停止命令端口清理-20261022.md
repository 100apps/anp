# macOS 原生包 stop 命令端口清理修订

本轮 CLI 修订为 `0.2.1-platform-poc`，已同步源码、构建目录与本机运行目录。没有启动项目服务，也没有用真实外来应用作为终止测试对象。既有 `0.2.0-platform-poc` 压缩包及其验收证据保持不变；本轮没有重新生成压缩包，后续 `make dist` 输出 0.2.1 文件名。

## 使用方式

```sh
./anp stop                 # 停本目录服务；外来端口占用列出清单并确认
./anp stop -y              # 不询问，直接停止配置端口的占用进程
./anp stop --yes           # 与 -y 相同
./anp stop --services redis -y
```

检查当前 `config/anp.json`（没有则用 defaults/anp.json）的端口，包括 ClickHouse 原生端口、Meta 管理端口。被本机配置覆盖的旧默认端口不在清理范围。`--services` 按已有依赖选择规则限定服务及附属端口。启动仍拒绝接管外来监听，`start -y` 会报错。

## 停止规则

1. 按依赖逆序停止本目录服务。失效的进程记录不会成为直接终止外来 PID 的依据，也不会阻断后续端口确认。
2. 汇总剩余监听的 PID、程序名和端口，同一进程多个端口仅操作一次；不输出完整命令行参数。
3. 普通 stop 询问 y/yes。拒绝或 stdin 结束不终止外来监听，返回非零退出码；-y/--yes 跳过询问。
4. 发送 SIGTERM；10 秒后仍占用原端口、出生时间仍匹配才发送 SIGKILL。只操作目标 PID，不终止其整个进程组。
5. 进程身份更换、自动重启、无权限或无法识别监听者均不会伪报成功；新 PID 不自动追杀，端口残留时报错。

本机目录已同步 `runtime/control.py`、README、版本和不可变清单，数据及私有配置保留。原生目录仍为 `var/native/run/anp-macos-arm64`。
