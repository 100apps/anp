# macOS ARM64 原生目录发行包 PoC

日期：2026-10-22（上海）。测试机器：macOS 26.5.1 / Apple Silicon。

当前状态：**原生构建、目录包和实际压缩包解压后的 12 项真实检查均通过。** 此记录不代表全功能 Supabase 或正式跨平台发行。

## 用户入口与目录

```sh
make build          # 自动准备 Redis submodule；下载校验官方产物；生成本机目录
make native-check   # 独立目录、离线与真实服务验收
make dist           # 按构建清单生成 tar.gz 和 SHA256
```

生成目录：`var/native/build/anp-macos-arm64/`。

压缩包：`var/exports/anp-0.1.0-poc-macos-arm64.tar.gz`，304,324,684 字节，约 290 MiB。

SHA256：`63f8a395038e4d5520d4b5c9080802c377170d1fbb29200f71d002f33d266643`。

解压后直接执行 `./anp start`、`./anp status`、`./anp stop`。首次启动自动生成独立数据库和密钥，普通用户运行，无需 Docker、Homebrew 或系统 Python 作为应用运行依赖。构建仍需要 Git、Python、Xcode 编译工具和首次下载网络。

```text
anp-macos-arm64/
├── anp
├── tools/{uv,python,node}/
├── storage/{postgres,redis}/
├── platform/{postgrest,litellm}/
├── runtime/
├── defaults/
├── config/
├── manifest/                  # 文件摘要、来源锁、许可证、原生库检查
└── var/                       # 首次运行生成，发行包不携带
    ├── data/
    ├── logs/
    ├── run/
    ├── cache/
    └── secrets/
```

默认只监听 127.0.0.1：PostgreSQL 55432、Redis 56379、PostgREST 53300、LiteLLM 54000。实际验收使用独立空目录和随机空闲端口。构建目录存在运行数据时拒绝覆盖；make dist 排除配置、秘密和运行数据。原 Docker 构建保留为 make docker-build，make build-multi 保留原行为。Linux 原生包尚未实现。

## 实际修改与原因

1. 新增 native/build.py、原生锁、运行管理与独立验收；Makefile 的 make build 改为目录交付，make dist 生成归档，旧 Docker 入口显式保留。
2. 官方 PostgreSQL 包的 bin 包装脚本缺可执行位，构建时补齐。包内 libiconv 的签名校验失败，构建时重新做本机 ad-hoc 签名；原始归档摘要与安装后的文件摘要分别记录。
3. 官方 PostgREST Mac 包引用 Homebrew libpq，改为引用随包 PostgreSQL 的 libpq；通过真实 API 验收检查兼容性。删除 PGXS 开发/回归工具，避免携带指向上游 /nix/store 的开发程序。
4. LiteLLM 仅安装 proxy extra 时健康检查可用，但匿名 API 请求因缺少 Prisma 返回 500；补齐冻结依赖后，真实匿名拒绝与 master key 访问再验。
5. 管理器通过安装根路径定位组件，所有应用状态写本包 var；停机后可搬移含空格/中文的目录，数据库、配置、密钥保持。PostgreSQL 使用 TCP，避免长路径 Unix socket 限制。
6. 加入外来端口拒绝、PID 出生时间/目录/进程组核验、启动失败回收和数据覆盖保护。关闭继承宿主数据库/模型环境与 dotenv 自动发现，Python 入口使用隔离模式与 -B。
7. 离线验收只限制应用/初始化进程；macOS setuid ps 无法放进该 sandbox，管理器在外执行进程核验。应用阻断外网与 /opt/homebrew、/usr/local、/nix 读取，管理逻辑不进行外部下载。
8. 本机曾因临时副本遇到磁盘不足；只清理本轮探针和临时 venv。目录回归采用 APFS 独立 inode 的写时复制，归档回归仍从实际 tar.gz 解压，不把硬链接测试当作解压证明。

## 范围边界

- PoC 只包含上述七个组件、四个服务。没有 Realtime、Langfuse、Studio、Supabase Auth/Storage、RustFS、ClickHouse、DBX 或业务工作台。
- PostgREST 初始化独立 anp_poc schema；匿名只读、JWT 的 anp_user 可写。这不是完整 Supabase Auth/RLS 产品验收；也不承诺 Docker 版全部 78 个 PostgreSQL 扩展可用。
- LiteLLM 没有配置供应商或模型；只验证网关进程与鉴权，远程模型调用次数 0。
- 仅在本机 macOS 26.5.1 ARM64 验证；未验证其他 Mac、Linux、生产并发或长期稳定性。ad-hoc 签名不是 Apple notarization，不宣称已经完成正式对外发行。
- 全部测试在本工作区独立目录完成，不修改既有 Docker 数据、相邻项目或现有 DBX 配置。没有提交、推送或发布本轮原生代码/归档。
