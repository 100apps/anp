# macOS 平台原生目录包 PoC：Supabase 与 Langfuse

本轮在原来的 macOS ARM64 目录包中加入 Supabase 和 Langfuse，保留 tools、storage、platform 分层。Realtime 不加入。独立目录与正式压缩包各自的 20 项完整验收全部通过。验收时，正式运行实例从该压缩包独立解压后启动，13 个服务全部就绪。随后已按用户要求停机；CLI 后续修订见 [停止命令端口清理报告](macOS停止命令端口清理-20261022.md)。本报告的 20 项归档验收和 SHA256 仅对应历史 0.2.0 制品。

## 交付与目录

```sh
make build
make native-check
make dist
python3 native/check.py --archive var/exports/anp-0.2.0-platform-poc-macos-arm64.tar.gz
```

构建目录为 `var/native/build/anp-macos-arm64/`，版本为 `0.2.0-platform-poc`。保留上一版 `0.1.0-poc` 压缩包；需要精简模式时执行 `make build NATIVE_PROFILE=poc`。Docker 构建仍是 `make docker-build`。

```text
anp-macos-arm64/
├── anp
├── tools/{uv,python,node}/
├── storage/{postgres,redis,clickhouse,rustfs}/
├── platform/
│   ├── postgrest/、litellm/
│   ├── auth/、storage-api/、meta/、studio/
│   ├── gateway/
│   └── langfuse/{web,worker,prisma}/
├── runtime/
├── defaults/anp.json
├── config/
├── manifest/
└── var/{data,logs,run,cache,secrets}/   # 首次运行生成，排除在归档之外
```

Supabase 的官方原生归档保留各自匹配的 Node 和动态库目录；Langfuse 使用 tools/node。业务对象经过 Supabase Data API/RPC，文件经过 Supabase Storage；底层 PostgreSQL、RustFS 不作为业务直接访问接口。验收中的 SQL 仅用于初始化受控测试表、函数和 RLS 策略。

归档 SHA256：`b22fa90f04678c91c8ec9036596e519458abc1608d7f10c7b4050e9aa537aa21`。压缩包约 1.60 GiB，目录实际占用约 6.2 GiB（文件系统分配值）。

## 启动和入口

```sh
./anp verify
./anp start
./anp status
./anp config-path
./anp stop
ANP_OFFLINE=1 ./anp start
```

默认统一入口为 `http://127.0.0.1:58000/`。Studio 位于根路径，Auth、Data API、Storage 分别位于 `/auth/v1/`、`/rest/v1/`、`/storage/v1/`，Langfuse 位于 `/langfuse/`，LiteLLM 位于 `/litellm/`。原生网关使用官方 Caddy；本轮没有修改 Docker 的 Envoy 交付。

本机 Meta 默认端口 58080 已有 CloudShell 监听，启动器在初始化前拒绝接管；随后为实例选择端口时，Worker 默认端口 53130 的绑定探测也暂不可用（未查到对应 LISTEN，未将其认定为外来服务）。仅在该实例 config/anp.json 中将两者改为 49403 和 49404。统一入口仍为 58000，默认配置和压缩包未修改。覆盖记录见 var/native/evidence/platform-live-port-overrides.json。

13 个服务共配置 15 个 TCP 监听端口，包括 ClickHouse 原生协议端口、Meta 管理端口。全部要求绑定 127.0.0.1，附属端口也参与启动前占用检查。默认值见 `native/defaults/platform.json`。

首次运行在 `var/secrets/runtime.json` 生成本包独立密码和 API key，权限为 0600。Langfuse 本地管理员邮箱为 `admin@anp.local`，密码在该私有文件中；报告不记录秘密值。Auth 为本机开发启用邮件自动确认，没有接入真实邮件服务。不要将此配置直接暴露到公网。

## 发现的问题、修复与原因

| 问题 | 修改 | 原因与验证 |
| --- | --- | --- |
| Auth 官方迁移向 postgres 角色授权，但 PoC 管理员原来只有 anp | 增加无登录 postgres 兼容角色，保留 anp 管理员；建立独立 Auth/Storage/Langfuse 数据库身份 | Auth 迁移、注册、密码登录及 token 访问 PostgREST 实际通过 |
| Studio 默认读写身份为 supabase_admin | 显式配置读写身份 anp、只读身份 anp_studio_reader | 真实 Studio SQL 查询从认证失败变为返回 SELECT 1 结果 |
| Meta 默认额外打开主端口加一的管理端口，曾与 Studio 测试端口碰撞 | 显式配置 PG_META_ADMIN_PORT，并纳入端口清单和归属检查 | 全部监听端口必须属于本目录进程组且只绑定 loopback |
| ClickHouse watchdog 改写进程名，破坏原来的 argv 归属校验 | 关闭该内置 watchdog，由目录管理器管理生命周期 | 原生启动和停止可受控完成 |
| Langfuse 的 Next 服务将进程名改成 next-server | 在出生时间、独立进程组之外，同时核对本包 Node 可执行文件和 Langfuse 工作目录 | 增加外国进程拒绝测试，并执行含中文、空格目录的真实 Mac 进程验证 |
| pnpm 12 拒绝向工作区之外 deploy | 先在构建工作区部署生产闭包，再移动到运行目录 | 不依赖开发工作区的绝对路径来启动 |
| pnpm 部署后存在多个 Prisma 快照，安装副作用生成的空客户端导致 Worker 启动失败 | 以 Web 追踪输出中经过实际 schema 生成的客户端为依据，修复所有 Worker 加载快照；构建时实际 require 验证枚举 | Worker 启动，以及真实 OTLP → Worker → ClickHouse 查询读回通过 |
| 官方 RustFS CLI 拆分含空格的绝对 volume 路径，导致冷启动找不到卷 | 在数据目录中启动，传相对 volume 参数 . | 中文和空格目录的真实原生启动及完整搬移重启验收通过 |
| 上游 Studio 原生归档带有默认 .env | 从发行目录移除环境文件，配置由启动器注入；重封包并复验 | 不读取或输出默认环境文件中的值，确保归档不携带环境配置 |
| Langfuse 的 /langfuse/ 会重定向到 /langfuse，与网关补斜杠规则冲突 | 网关同时代理两个根路径形式，保留 Next 的规范重定向 | Caddy 配置验证通过，最终 Cookie/页面资源验收覆盖实际根路径 |
| 分组件 Rust 安装器的 LLVM 库不在 rust-objcopy 相对查找位置 | 在项目自有工具链中补齐相对符号链接 | 不依赖宿主 Homebrew LLVM；工具实际执行验证通过 |
| 完整冷启动时 Langfuse Web 超过原先统一设置的 768 MiB JS 堆上限 | Langfuse Web/Worker 单独设置 2048 MiB 堆上限，其他 Node 应用维持原限制 | 堆上限不是预分配；以完整独立包冷启动和 API 验收复核 |
| 启动过程可能出现早期服务退出或临时不健康 | 启动结束复核全部服务，不允许返回成功但 ready=false；保留失败回滚和 PID 防误杀 | 生命周期安全测试、完整服务验收分别覆盖 |

最终候选以完整构建为基础，对环境文件排除、启动器和路由修复进行了增量重封包；同步更新不可变文件清单、构建输入摘要和适配记录。相同修复已经写入构建输入，后续 make build 自动包含这些修改。最终验收针对重封包后的实际归档执行。

过程中有一次缓存重建与联调副本复制并发，导致测试副本复制失败。该副本已删除，没有作为通过证据；最终制品构建与验收副本串行准备，之后从实际归档再次验证。

## Docker 清理

经用户授权，清理未被容器引用的镜像和构建缓存，没有删除容器、数据卷或项目数据。初次清理遇到 Docker/containerd 的 input/output error，经过虚拟机正常停止和重启恢复，再执行清理及文件系统 trim。

Docker 报告回收构建缓存约 60.42 GB、镜像约 3.507 GB。两者是 Docker 的报告值，不能直接当作 Mac 物理释放量相加。trim 后实际可用空间曾回升到约 70 GiB；后续构建还会占用空间。虚拟机已停止。证据见 `var/native/evidence/docker-cleanup.json` 及同目录清理日志。

## 范围和限制

本轮只验证本机 macOS ARM64；Mac Intel、Linux 原生目录包、Windows 尚未验证。Realtime、Edge Runtime、Logflare、Vector、imgproxy、Supavisor、PgBouncer、DBX 和业务工作台不在本包内。没有配置真实模型供应商、邮件或第三方 OAuth，不将本轮合成 trace 当成真实模型调用或业务线上效果。

包内保留官方运行依赖闭包，尚未做跨组件去重。签名使用本机 ad-hoc，不包含 Apple notarization。升级前停止服务并备份 var/ 和 config/；构建检测到已有运行数据会拒绝覆盖。压缩包按不可变清单生成，排除运行数据、操作员配置、日志和秘密。
