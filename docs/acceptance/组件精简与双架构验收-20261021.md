## 发现与修复的问题

1. **Realtime Cookie 长度导致进程退出。** `libcluster_postgres` 把 Erlang Cookie 用作 PostgreSQL LISTEN 频道，原 96 字符超过 63 字节限制。改为从持久化 Secret Key Base 派生稳定 48 字符 Cookie；不旋转已有数据密钥。单元回归先复现失败，修复后双端真实订阅通过。
2. **PostgreSQL 17 的 Realtime tenant 权限迁移失败。** 显式 `GRANTED BY supabase_admin` 要求 ADMIN OPTION；初始化为该角色授予三个 API 角色的 ADMIN OPTION，并修复旧角色 LOGIN / REPLICATION 属性。
3. **Auth 在空数据根启动失败。** `auth.uid/role/jwt` 的函数归属不一致，Auth 迁移不能替换由 postgres 拥有的函数。三者统一归属 `supabase_auth_admin`，保留 API 角色 EXECUTE 权限。隔离 PostgreSQL 探针先复现失败，再证明同一迁移角色可以替换函数并回滚。最终双架构空数据根启动均通过；验收脚本保留实际 SET ROLE + CREATE OR REPLACE + ROLLBACK 检查。
4. **Studio / Langfuse 构建内存与 worker 过量。** 显式限制页面 worker 为 2、Next 堆为 4GiB；Studio 16.2 的 Turbopack 目标内存设为 6GiB。Langfuse 16.3 不支持该选项，由独立类型检查捕获并移除。Langfuse 打包与必需的独立类型检查顺序执行。两架构完整生产构建均通过。
5. **Langfuse 配置补丁误中注释。** 锚点限定为真实 `experimental` 配置，增加先失败后通过的补丁回归测试。
6. **基础镜像漂移、下载偶发中断与主机依赖差异。** 固定官方多架构 manifest 摘要；官方 LiteLLM Admin 下载增加有界重试、保持 URL / SHA256 固定；前端项目指定官方 npm registry。ECS 只在任务目录安装固定官方 Node 24，不修改主机 Node 20。

构建参数依据固定 [Next 16.2.11 官方源码](https://github.com/vercel/next.js/blob/v16.2.11/packages/next/src/server/config-shared.ts)。早期失败日志、临时修复范围和失败冷启动数据保留；它们不作为最终镜像通过证据。
