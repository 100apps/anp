# deep_dub 工作台接入

## 已运行验证

2026-10-18，`apps/deep_dub/app.toml` 已启用。工作台访问 `http://127.0.0.1:8089/workbench/apps/deep_dub`，沿用 Supabase 登录、工作空间与权限。

- 通过真实浏览器创建 `[工作台验收] 项目登记`，来源为 `example.invalid` 验收地址。只创建项目，不触发来源下载或生产计时。
- 项目页展示真实运行、来源、分段、译文、说话人、参考、音频候选、选版、时间线版本、背景、成片、审核、评分、私有产物和执行尝试。记录使用分页；未测分数显示“未测”，不会填为通过。
- 当前版本界面是只读记录与证据详情，项目创建和取消使用已有受限业务服务。不能把版本记录列表称为多轨编辑器或媒体试听已实现。
- 新增任务概览兼容查询，不使用 demo 的任务写入、通用节点执行或结果表。任务总数经现有调用者身份/RLS 的 RPC 统计，列表明确只显示最近记录。
- 实际 API 宿主 8181、Worker 8282 已注册独立业务路由。通用协调器跳过 `[execution].owner = "business"`；共享 Worker 密钥无法走这类业务的通用节点与 Studio 隐式管理员入口。
- 根 CLI 已加载业务自己的命令，支持父级 HTTP 选项继承及子命令显式覆盖。默认本地模式在无效 Web 地址下仍可读取，HTTP 与本地结果一致。
- 平台引擎从只读业务挂载目录加载解码子图，实际调用 8282 Worker，对两秒明确标记的验收视频完成租约、解码、证据保存和评分。图结束不意味着整片运行验收完成。

```powershell
uv run anp deep_dub projects list
uv run anp --transport http deep_dub projects list
uv run anp deep_dub runs get <运行ID>
uv run anp deep_dub projects records <项目ID> scores --offset 0 --limit 50
```

业务宿主扩展位于 `src/anp`，由当前 F5 源码进程运行；新增业务代码均保留在 `apps/deep_dub`。现有平台固定镜像未用临时文件打补丁。业务图变更通过只读挂载加载，平台重启前完成私有状态备份及独立卷恢复检查。若后续分发更新后的宿主安装包或平台运行器，仍需对应制品构建与验收，不把本机源码热更新当作新镜像已发布。

## 真实 Agent 验收中的修正

首轮真实 Agent 验证失败：运行 context 被服务器放进线程状态响应，本机核心图的内存检查点验证不足以推断 Agent Server 的行为。已取消该验收运行、保留失败线程，并改为由业务主机持有单次授权索引；图仅传运行/尝试 ID，通过部署环境的服务间凭据领取已授权任务。新真实 Agent 运行未接收作业令牌，其线程状态未发现三种凭据。详见 [执行委派](deep_dub执行委派.md)。

平台重启时浏览器曾遇到身份查询上游不可用。增加了“重新连接”入口；浏览器在后续热更新/重新查询后保留登录并恢复工作台。本轮没有单独模拟点击该按钮的故障恢复，不将其记录为已完成的按钮交互验收。
