# deep_dub 执行委派

## 已运行验证

2026-10-18，业务目录新增单次执行授权、独立 Worker 接口及 LangGraph 解码子图。业务图与平台执行引擎的边界如下：

1. 已登录用户通过业务 API `POST /api/apps/deep_dub/runs/{run_id}/decode-job` 请求授权。业务服务重新验证 Supabase 会话、工作空间、执行权限和产物读取权限，并固定阶段尝试、输入摘要与参数。
2. 返回限时的作业令牌。令牌不包含原用户 JWT；原会话保存在业务主机的 `.local/deep_dub/delegations`，不发送给平台执行引擎。有效期同时受用户会话到期时间限制。
3. `apps/deep_dub/flow/decode.py` 使用 LangGraph 的运行上下文传递作业令牌；状态只包含运行 ID、尝试 ID 和结果。Worker URL 由部署侧提供，不接受用户在图状态中指定地址。
4. 图调用 `POST /internal/deep_dub/jobs/{attempt_id}/decode`。Worker 校验令牌、尝试范围、有效期、当前运行状态，并重新验证原用户身份和权限；不能使用通用 Worker 密钥或原用户 JWT 代替作业令牌。
5. 实际 CPU 阶段执行租约、心跳、私有下载、全流解码与证据保存。重放返回同一冻结回执。取消或授权到期会等待本次进程停止，再结束请求；不能通过返回超时冒充物理停止。

Windows 授权目录取消宽泛的磁盘 ACL 继承，仅授予当前 Windows 用户和 SYSTEM 访问权限；已有继承文件也随目录收紧。Linux 分支使用目录 0700、文件 0600，尚未在 Linux 实机验证。不会把 `chmod(600)` 当作 Windows 读取权限保护。

本轮真实集成验证包括：

- 使用两秒明确标记的验收视频，经本机 LangGraph、临时 Uvicorn HTTP Worker、真实 Supabase/RustFS 和 CPU 运行器完成解码；同一令牌重放得到同一回执。
- 检查图状态历史及内存检查点存储，未出现作业令牌或原用户 JWT。此结论只覆盖当前本机图适配，不代表已检查平台 Agent Server 的持久化运行记录。
- Viewer 签发拒绝；错误运行范围、额外执行参数、过期令牌、取消后的运行均拒绝；原用户 JWT 和通用密钥不能直接访问作业接口。
- 专用测试用户在签发后撤权，即使令牌尚未到期也被拒绝，未创建设备租约。该账号验收后保留 viewer 角色，未修改其他账号。
- 用受控的三十秒 FFmpeg 替换解码体，执行过程中触及四秒授权截止后，实际子进程退出、阶段失败、租约释放。该测试验证截止清理，不代表媒体解码成功或整片生产通过。

测试入口：`tests/test_deep_dub_delegation.py`、`tests/test_deep_dub_delegation_live.py`。真实集成需显式启用 `ANP_DEEP_DUB_LIVE=1`，并先加载 V3 环境。
