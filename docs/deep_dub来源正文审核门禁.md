# deep_dub 来源正文审核门禁

状态：实现来源正文覆盖的审核方法约束；当前真实来源仍未完成正文裁决，不能解除待审。本文的数据库合成夹具不是内容质量证据。

## 修复的问题

原 `deep_dub_record_audit` 允许来源 `transcript_coverage` 以 `technical/passed` 登记；成片必需门禁随后只检查最新记录为 `passed` 且关联证据。样本覆盖、ASR 词差异或精确匹配等技术测量因此可能被错误地当成完整正文复核。

迁移 `018_source_content_audit_gate.sql` 同时更新登记函数和成片使用的 `deep_dub_assert_latest_audits`：

- 来源 `transcript_coverage` 的通过必须声明 `human` 或 `independent_model`；Python 契约与数据库 RPC 都拒绝 `technical/passed`。
- 技术方法仍可以记录 `failed`、`not_measured`；时长、音轨等技术审核不受影响。未测无需伪造通过。
- 消费门禁同时检查方法，历史技术通过也不能被计入；不回退使用更早的一条通过。最新失败或未测仍会阻止验收。
- 迁移没有数据 UPDATE/DELETE，不改历史状态、审核行、运行起点或成片通过时间，不自动签发新的审核。内部消费函数继续不向普通用户开放。

审核作者有权限且选择了正确方法，只满足记录契约；仍须真正完成与当前版本绑定的独立复核。方法字符串本身不证明听审或正文正确。

## CLI 与共用服务

补齐通用 CLI 登记入口，默认直接调用业务服务；根参数 `--transport http` 对接现有相同 POST 接口：

```powershell
uv run anp deep_dub audit <项目UUID> --input <已有复核证据的审核JSON> --request-key <稳定键>
```

JSON 沿用 `AuditInput`，审核主体、质量修订、规则版本、状态、方法及证据 UUID 均由现有契约校验。没有可据以通过的复核证据时，应保持 `not_measured`。此入口不会代替听审或自动生成内容通过记录。
