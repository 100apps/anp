## v5 校准与完整来源实测

v4 的十份原始回复全部判定正确、五处关键内容正确，但三处差异泛称 meaning，细分标签正确率只有 2/5。v5 明确区分内容能力与分类能力：十个判定必须全对，五个差异的关键听到内容必须准确；分类标签单独评分并原样显示，不再以标签细分作为执行正文的前提。这是显式协议变化，不将旧失败转成成功。测试覆盖数字听成另一个错误数、否定句仍含否定、专名听成第三个人等情形，不能碰巧判差异就通过。

## 原意见不能当作正文裁决

原始模型统计为未报差异 1、报差异 43、不确定 0。实际检测到 **33 个窗口、104 条意见的候选引文与听到引文一致**；末窗甚至同时给出“不匹配”和“完全相同”的理由。因此 43 仅是模型报差异数，不能当作真实错误数；简单合成校准通过不能证明长稿质量合格。

`auditory-excerpt-grounding-v1` 只做 NFC 与空白规整后的严格引文一致检查，保留大小写、标点和否定，不自动修正任何原文、标签或 verdict。一致引文无法单独支撑差异；不同引文也不因此获得真实性证明。原 JSON 和原失败审核 `09b38747-3bdd-46b5-9b83-5af327f2ffcc` 保留，新追加技术未测审核 `fc85bdc3-5159-4307-a0ce-f5c50ff2691b`，来源仍不通过。

原 8 项评分保持，新增相同引文意见数和待核实窗口数，共 10 项；Langfuse 实际读回用户与 session 正确。恢复首次 15.98 秒失败于观测行唯一性假设：实际 API 返回同一 span 的两条逐字段完全相同行，身份全部正确。查阅固定上游 V4 events 查询后，验证改为仅容许完整响应字段完全相同的重复，任何身份或字段冲突仍失败，原重复响应私有留存。最终同一尝试的 API/两 CLI 恢复读取 12.61 秒通过，没有再次启动模型。

正式工作台已实际验证 44 窗口分页、33 项引文待核实筛选、10 份校准列表；末窗 2580–2586.30825 秒实际播放到终点自动暂停。切换并播放校准原音后返回来源，DOM 只保留一个已暂停播放器，无媒体错误。这只证明播放交互，不是人工听审通过。[界面证据](evidence/deep-dub-omni-grounding-20261019.jpg)。
