## 业务代码边界

业务目录为 `apps/deep_dub/`，目标包含 `api/`、`services/`、`nodes/`、`flow/`、`ui/`、`migrations/`、`evaluators.py` 和 `app.toml`；当前落地关系与版本契约，业务不烘焙进平台镜像。

- API、HTTP CLI 和 Web 调用同一组业务服务。
- 本地 CLI 默认直接调用这些服务和节点，不要求启动业务 Web/API/Worker；仍连接平台身份、存储及模型依赖。
- HTTP 执行通过 Agent Server 调用业务 Worker。Flow 是业务拥有的图定义，节点负责业务逻辑；平台负责执行、checkpoint、追踪与部署。
- GPU/CPU 执行端是业务计算进程，不成为第五种基础存储或混进平台镜像。远端执行与本地调用使用相同的作业输入、产物和幂等契约。

## Supabase 关系模型

暂定沿用现有 `platform` schema 和用户身份。以下所有业务表均以 `deep_dub_` 开头；表不是整个旧 `task.json` 的单字段副本。JSONB 仅用于提供商参数、测量明细和原始回执等可变结构。

| 表 | 主要字段与关系 | 约束重点 |
| --- | --- | --- |
| `deep_dub_projects` | `id`、`workspace_id`、名称、语言、`source_id`、当前分段集、`row_version` | 根对象；编辑使用期望版本号，拒绝覆盖他人更新 |
| `deep_dub_quality_profiles` | 工作空间、档位 key、revision、规则与摘要、来源 | 不可变规则修订；默认 high；run/render 绑定修订，禁止自动降档 |
| `deep_dub_sources` | 项目、来源 URL、原片 artifact、媒体时长/轨道、来源核验 | 原片与 SHA 不可原地替换；变更建立新来源版本 |
| `deep_dub_artifacts` | 工作空间、对象路径、SHA256、字节数、媒体类型、采样率/时长、生成 attempt | 工作空间内按摘要去重；对象私有；不得返回宿主机文件路径 |
| `deep_dub_runs` | 项目、`platform.tasks.id`、执行模式、flow/quality_profile 修订、输入快照摘要、生命周期时间 | 一个真实生产轮次对应一个平台任务；重试不重置最早起点 |
| `deep_dub_stages` | run、节点名、分片键、输入摘要、当前状态、当前 attempt | 唯一 `(run_id,node,partition_key,input_hash)`；整集与逐段阶段统一建账 |
| `deep_dub_stage_attempts` | stage、attempt_no、设备租约、排队/加载/执行/结束时间、错误、产物清单 | 唯一 `(stage_id,attempt_no)`；每次真实尝试保留，不把返修改成首次成功 |
| `deep_dub_speakers` | 项目、稳定角色标识、显示名 | 角色身份与可编辑显示名分开；人工身份判断有独立测量状态 |
| `deep_dub_cues` | source、来源版本、cue序号、原文、起止时间、角色 | `0 <= start_ms < end_ms`，来源版本内序号唯一 |
| `deep_dub_segment_sets` | 项目、revision、来源/分段策略版本、父分段集 | 重分段产生新集，旧段与旧结果保留 |
| `deep_dub_segments` | segment_set、稳定段标识、角色、原文、起止时间 | 复合唯一 `(segment_set_id,id)`；段时间受源时长约束 |
| `deep_dub_segment_cues` | segment、cue、顺序 | 显式多对多来源关系，不能只存一组没有外键的 cue ID |
| `deep_dub_translations` | segment、revision、中文、模型/提示版本、输入上下文摘要、独审状态 | 不可变候选；区分生成与独立复核，不覆盖当前文本 |
| `deep_dub_voice_references` | speaker、revision、来源片段、原版/处理版 artifact、滤镜参数摘要、审核 | 本集固定音色；更新参考使相关下游输入摘要变化 |
| `deep_dub_emotion_references` | segment、source 修订、准确原声窗口、artifact、处理摘要 | 与固定音色分开；引用原始窗口而非可编辑配音落点；切段/换源失效 |
| `deep_dub_audio_attempts` | segment、translation、voice_reference、emotion_reference、生成/派生关系、参数、WAV artifact、时长 | 生成次数和派生变速次数分别记录；绑定准确文本、固定音色和逐段情绪版本 |
| `deep_dub_audits` | 被审对象、输入摘要、审核器/规则版本、状态、证据 artifact、人工/自动来源 | 内容、数字/专名、时序、原语泄漏等独立记录；未知不当作通过 |
| `deep_dub_selections` | segment、revision、translation、audio_attempt、审核集合、选择人/时间 | 选择保留历史；原子 RPC 校验候选属于同段、同版本并具备必需审核 |
| `deep_dub_selection_audits` | selection、audit；两端带工作空间与项目复合外键 | 已实施的补充关联表，封存选版后不可追加或删改 |
| `deep_dub_timeline_revisions` | 项目、分段集、revision、输入摘要、创建人 | 不可变组合；当前指针用期望版本提交，render 引用准确修订 |
| `deep_dub_timeline_clips` | timeline 修订、segment、selection、播放起点、组合参数 | 复合外键校验空间/项目/分段/选版归属；位移和组合变化触发组合审核 |
| `deep_dub_backgrounds` | source、revision、分离/净化 artifact、模型/分块计划、泄漏和事件审核 | 区分原版、处理版、诊断 removed 轨；诊断轨不参与成片 |
| `deep_dub_renders` | run、revision、strategy_key、quality_profile/timeline 修订、选版快照摘要、背景版本、对白/混音/字幕/视频 artifact、完整解码回执 | 制品绑定冻结输入快照；禁止后改译文让旧成片看起来仍有效 |
| `deep_dub_scores` | run、stage_attempt、指标、规则版本、值、测量状态、证据、Langfuse ID | 分数与对应版本绑定；未测值为 null，不能填 0 或默认 1 |
| `deep_dub_observation_outbox` | stage_attempt/score、稳定事件ID、事件类型、投递状态、重试时间 | 事务内登记，幂等补发；不能因进程重启重复记分或丢失观测 |
| `deep_dub_publications` | render、平台、发布修订、幂等键、上传/投稿/发布状态、回执、公开地址 | 同一 render 重试不重复投稿；已提交但回执丢失时先查证，不盲重发 |
| `deep_dub_devices` | 主机、设备 UUID、GPU/CPU 类型、能力、容量、健康、当前 fencing 序号 | CPU 与 GPU 分开计量；不按可用显存猜测任务归属 |
| `deep_dub_device_leases` | device、stage_attempt、owner、token摘要、fence、租期/心跳/释放 | 领取/续租/释放走受限 RPC；过期不等于物理任务已停止 |

业务表都包含 `workspace_id`。父表建立 `(workspace_id,id)` 唯一键，子表使用相同两列的复合外键；只有一个普通 UUID 外键不足以阻止跨工作空间拼接关系。引用现有 `platform.tasks` 时也需要补齐该复合唯一键，不能只依赖应用层检查。来源/项目之间的当前指针在迁移实施时采用可延迟外键或拆成单独选择记录，避免初始化循环引用。

媒体时间使用整数毫秒，生产事件使用 UTC `timestamptz`；设备耗时另存单调计时值，不能直接用未校时的两台主机时间相减。

## 权限与作业提交

1. 复用 Supabase 登录、`platform.members` 与业务 action；读项目、改稿、执行、审核、发布分别鉴权。
2. 根表和子表都启用 RLS；所有 INSERT/UPDATE 需要 `WITH CHECK`，复合外键同时保证关系归属。视图默认遵循调用者权限。
3. 选择版本、领取作业、提交结果、申请发布需要原子 RPC；锁顺序固定，校验期望版本、工作空间和输入摘要。若必须使用 SECURITY DEFINER，固定 search_path，显式鉴权并限制 EXECUTE 权限。
4. 前端和 CLI 不拿 service_role 来绕过权限。远端 Worker 的作业授权仅绑定一个 stage_attempt、输入摘要、有效期和允许的产物；具体签发/续期与撤销机制需要实施后实测，不能当作现有平台已经具备。
5. 长任务期间权限撤销、取消或输入版本变化，都必须在结果提交时重新校验。过期 Worker 即使算完，也不能覆盖新 attempt。
6. 对象按工作空间及项目隔离，使用短期授权访问；需测试未登录、跨工作空间、过期链接、越界路径和音视频 Range 请求。

## 图与节点

计划执行顺序如下，实际并发还要服从设备容量与模型驻留约束：

```text
创建 run / 固定策略 / 记录最早时间
  → 下载与源核验
  ├→ 字幕/ASR 候选 → 可信原文与角色 → 分段集
  │    → 翻译候选 → 独立语义复核
  │    → 固定音色参考 → 代表段预检
  │    → 分段 TTS → 当前 WAV 回转录 / 内容 / 时序审核
  │        └→ 有预算的局部返修 → 重审新版本
  └→ 分离背景 → 净化 → 泄漏及事件审核
两路所需输入就绪
  → 冻结选版快照 → 对白时间线 / 混音 / 字幕 / 封装
  → 完整解码 / 响度 / 时长 / 选版一致性验收
  → 投稿 / 回执查证 / 发布状态查证
```

每个节点只接收对象 ID、版本、摘要和必要参数。大文件放对象存储，不塞进 LangGraph checkpoint 或 Langfuse 输入输出。流式推进可以缩短等待，但不能让未经必需审核的产物进入最终成片。

返修策略保存原因、实际成本和剩余预算；失败分为暂时依赖错误、输入不合法、质量未通过、等待审核、取消。达到预算后保留 blocked 和证据，不能改成成功。LangGraph interrupt 的业务暂停与平台任务 running 的映射需要专门验证，不能让通用协调器把待审误判成完成。

## 幂等、版本失效与设备租约

- 操作键包含工作空间、run、节点/分片、输入摘要、规则/模型版本。输入改变产生新阶段，不能只用“项目ID+节点名”命中旧结果。
- 数据库提交先登记 attempt，再写临时对象并校验摘要，最后原子提交结果。中断留下的对象有可追踪归属，不能凭目录有文件就推定节点完成。
- 改译文、音色、分段或源窗，产生新下游输入摘要；保留旧结果及审核，不将旧通过状态复制给新版本。成片使用冻结选版快照，用户继续编辑不影响旧成片回溯。
- 租约领取锁定 device 行并递增 fence。续租失败或心跳超时先隔离设备；确认对应 PID/启动身份的作业已退出后才重新分配。数据库 fencing 能拒绝旧结果，不能自动释放真实 GPU 显存。
- 起步每张 16GB GPU 只允许一个重模型作业。ASR、分离、TTS 的重叠和模型驻留必须依据峰值显存/冷启动数据调整，不能假定两张卡可以任意叠加模型。
- CPU 抽音频、分块、封装和完整解码使用独立容量。保留 I/O、等待、模型加载和返修耗时；设备忙时进入可观测队列。

## 工作台功能对齐

工作台采用 shadcn/ui 的现有导航、表单、Table、Tabs、Dialog、Sheet 等组件；专业时间线与媒体同步由业务组件实现，不能把普通进度条当作多轨工作台。

- 项目列表：创建、来源、当前阶段、硬门禁、实际耗时/RTF、设备队列和失败接续。
- 编辑页：上方同步画面，中间可缩放时间线，下方分段表；右侧查看原文/译文版本、TTS 候选、参考音色与审核证据。
- 多轨试听：画面默认静音，原声、中文对白、背景原版/处理版分别 mute/solo/gain；拖动时间、逐段播放与长短句定位。
- 版本操作：生成候选、独审、选版、局部返修、重分段；显示版本失效和“尚未测量”，不隐藏失败 attempt。
- 运行/发布页：实时阶段与资源占用、输入/产物摘要、取消/续跑、最终解码回执与 B 站投稿/公开状态。
- CLI 提供相同业务操作并输出 JSON；使用期望版本号与幂等键，不能因绕过 Web 就跳过 ACL 或质量门禁。

## Langfuse 评分与完整计时

`user_id` 来自调用者身份；`session_id` 使用稳定 run ID；stage_attempt、设备、规则版本作为观测属性，父子 span 对应实际调用链。延迟上报通过 outbox/重试幂等写入，不能因为 Langfuse 暂不可用就丢失测量。评分本地业务库保存可验证证据，Langfuse 用于追踪与对照，不作为事务状态唯一来源。

| 阶段 | 计划指标 | 边界 |
| --- | --- | --- |
| 下载/源准备 | 来源完整性、轨道/时长、文本覆盖 | 不能把网站字幕存在当作内容通过 |
| 翻译 | 语义、数字/专名、遗漏、上下文一致性 | 生成模型自评不冒充独立复核 |
| 音色/TTS | 文本与实际 WAV 一致性、内容差异、时长适配、失真、角色参考 | 音色身份和自然度未测时保持 unmeasured |
| 背景 | 原语泄漏、事件保留、分离伪影 | 自动抽样与人耳判断分别记录 |
| 成片 | 完整解码、响度/真峰值、时长差、字幕、输入快照一致性 | 技术门禁与主观质量分开 |
| 发布 | 文件一致性、投稿回执、公开状态 | 上传完不等于投稿或公开成功 |

根 run 从第一次真实排队/获取来源开始，包含下载、冷加载、设备等待、人工等待、失败与返修，到技术验收结束计算生产 RTF。另记录直到投稿回执及公开状态确认的交付墙钟，明确上传/站点审核耗时，不在展示中隐去。

历史阶段累计值不用于回填新 run 的时长。迁移回放可导入旧数据做功能测试，但最终目标必须使用新生产记录；不能复用历史成片或旧选中 WAV 冒充新完整生产。缓存命中、热模型与冷启动分别标注，最终依据平台验收账本的完整口径判断。

## 平台通过后的实施与验证次序

1. 先实现关系迁移与原子 RPC，验证跨工作空间外键/RLS、乐观锁、租约并发领取、失联隔离、旧 fence 提交拒绝。
2. 建立旧任务只读导入映射，保留历史 ID、版本、失败和未测项；旧目录保持原样。先验收工作台浏览/试听/选版与本地/HTTP/Web 一致性。
3. 接入真实模型和两台设备，跑短片与长短句/数字/多角色/事件声场景；每节点记录真实得分、冷启动与排队时间。
4. 用数据定位关键路径，调整分块、批处理、流水线、预检、有限返修与模型驻留；每轮完整保留失败，不只展示最快样本。
5. 最后新跑整片，核算完整生产 RTF≤0.5、验收实际媒体，再完成真实 B 站投稿与回执/状态查证。未达标时继续优化，不以局部测试替代。

## 设备只读预检查（2026-10-18）

两台主机实际可访问：本机 RTX 5060 Ti（16311 MiB）与 i9-13900K（24 核 / 32 逻辑 CPU），远端 V100-SXM2（16384 MiB）与 E5-2699 v4（22 核 / 44 逻辑 CPU）。这是硬件清点，不是性能结果。

远端采样时 GPU 利用率为零，但四个 audiocpp_server 进程合计已占用大部分显存，GPU 总用量 14917 MiB。尚未核对其任务归属，没有停止进程或卸载模型。实施设备租约时，必须先识别并接管或隔离这些既有进程；不得仅以利用率为零就宣告设备空闲。远端非交互 PATH 可找到 ffmpeg，未找到 uv，不能据此认定 uv 未安装。

只读命令与结果边界见 `docs/evidence/deep-dub-device-preflight-20261018.json`。没有下载、加载模型或启动配音任务；平台完整验收通过后再实施业务。
