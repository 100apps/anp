# deep_dub 远端取消与失联恢复

范围：真实 V100 已有 IndexTTS2 常驻服务；只管理本工作区业务作业和对应服务槽位。不是整张 GPU 独占，也不是 CUDA 内核取消。整片质量、完整墙钟 RTF≤0.5 与 B 站回执继续，不能用本轮短句验收替代。

## 取消的实际行为

在独立验收项目和新运行中登记新的 26 秒原片、人工测试中文和原声参考，发送一个请求。观察到远端业务进程存活、持久状态为 `submit_intent` 后，请求取消。业务等待当前同步请求的可信终态，不结束其他作业或模型。

真实专项通过，测试墙钟 47.37 秒，取消到响应观察值约 22.47 秒。远端节点最终产生合法 WAV，但本机尝试保持 cancelled，HTTP 返回 409，不提交音频候选，租约确认 operation_stopped 后 released。远端常驻服务保留。发送意图与进程存活不能证明当时恰在执行 CUDA 内核，不将该检查写成内核中断通过。

## owner 失联的恢复契约

新增 `services/resident_recovery.py`、023 迁移、同契约 HTTP/默认本地及 HTTP CLI：

```powershell
uv run anp deep_dub recover-resident <attempt-id>
uv run anp --transport http --endpoint http://127.0.0.1:8181 deep_dub recover-resident <attempt-id>
```

HTTP 为 `POST /api/apps/deep_dub/attempts/<attempt-id>/recover-resident`。复用当前用户和空间，每次要求执行与设备管理权限；不接收客户端伪造的远端证明或服务地址。

- 持有与正常执行相同的本机槽位锁。正常 owner 仍持锁时拒绝；持久日志必须精确匹配当前尝试、远端作业 ID 和冻结请求摘要。
- 通过已有信任 SSH 读取既定作业，不重新提交。校验节点摘要、实际服务 PID/启动时钟/boot ID/执行器/权重，以及当前请求完整终态和 helper 退出。
- 重新检查本工作区其他同服务作业都已停止；无法确认时保持隔离，不结束模型来制造空闲。
- 数据库只接受原常驻服务槽位的相同服务身份、准确租约集合和过期 owner；不放宽原物理 GPU 探针的外部进程约束。
- 只读取租约表授权的非秘密列，不读取 token_hash 等私密列，也不扩大 SELECT 权限。
- 失联尝试只能以 `WORKER_LOST` 失败收尾，outputs 为空、monotonic_seconds 为 NULL。即使远端已有合法 WAV，也不冒充正常成功提交。取消尝试保持取消，原运行/排队起点不改。

## 已运行验证与保留的失败

8 项独立 PostgreSQL 检查通过（5.60 秒）：过期服务槽位恢复、原运行保持、失败而非成功、旧版本拒绝、仍存活 helper/未停止/错误作业/未知状态/节点摘要缺失与有效 owner 租约拒绝。它们不代表实际远端执行。

真实 owner 失联使用测试自己创建的本机 Python `Popen` 进程。观察到远端 helper 存活和发送意图后，只通过该进程句柄终止本测试 owner；没有扫描名称杀进程，没有结束平台或远端模型。远端继续到完整终态。

首次专项在 owner 退出后因租约查询使用 `select *` 而被列权限拒绝（29.12 秒）；原计划、作业与日志保留。服务和测试均改为显式非秘密列，重新构建并由 Compose 部署后，只恢复原尝试，不重新生成。HTTP 恢复和本地服务重复读取通过（21.69 秒）；attempt 失败、无伪造单调耗时、租约释放、无成功候选，原 run 对象逐字段不变。

两次后续恢复检查遇到 SSH 观察失败（7.71 秒、18.53 秒），没有据此认定模型退出或重新发请求，原成功恢复状态保留。后续同尝试检查 43.42 秒通过，实际默认本地 CLI（不可用 HTTP endpoint）与 HTTP CLI 的恢复结果保持同一失败尝试，没有再次运行模型。取消和失联阶段在 Langfuse 的实际观测均核对用户、session 和 acceptance 环境。
