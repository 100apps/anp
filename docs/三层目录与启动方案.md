# 目录与启动设计

```text
anp3/
├── compose.yaml                  # 唯一运行服务 toolbox
├── compose.build.yaml            # 九个源码构建目标，不用于运行
├── Makefile
├── docker/
│   ├── toolbox/Dockerfile        # 生产产物组装
│   ├── toolbox/runtime/          # 配置、依赖图、独立UID、健康与退出管理
│   ├── toolbox/versions.lock.json
│   ├── platform/                 # 固定源码对应的上游生产配方及必要适配
│   └── source-recipes.json       # 原始与适配配方哈希
├── platform/sources/             # 八个真实Git submodule
├── business/
│   ├── src/anp_business/         # Workflow、Deep Agents、译配与HTTP扩展
│   ├── ui/                      # shadcn风格工作台，pnpm锁定
│   ├── supabase/migrations/      # 对象关系、外键、RLS
│   ├── langgraph.json           # 三个图和HTTP扩展入口
│   └── uv.lock
├── config/                      # 脱敏示例
├── scripts/                     # 构建、开发、安全停止、验收
├── tests/runtime/               # 服务依赖、选择和凭据隔离契约
├── .vscode/                     # F5前后端热重载
└── var/                         # 宿主日志、运行身份、译配输入；Git忽略
```

每个服务有独立固定 UID，不继承管理器全部凭据。PostgreSQL 保留官方 Nix 运行库，Storage 隔离 musl，Node22/24按上游ABI分别使用。没有嵌套 Docker、docker.sock 或 privileged。管理器以依赖顺序等待健康，失败有限重试，无关服务继续运行；整体健康只有全部选中服务就绪才返回200。

服务组：`storage`、`platform`、`langfuse`、`supabase`、`all`；也可逗号指定具体服务。默认自动补全依赖。接外部服务时设 `ANP3_AUTO_DEPS=0` 并在 `/data/config/services.json` 覆盖相应进程环境，例如只启动 `litellm` 并设置外部 `DATABASE_URL`。`config/services.json.example` 只是结构示例，Langfuse还需要完整配置外部PG、CH、Redis和S3。

持久化树：`/data/<服务>/`、`/data/config/credentials.json`、`settings.json`、`services.json`、`litellm.yaml`、`effective/`、`/data/logs/<服务>/`、`/data/run/`。`effective` 在启动生成，不手工修改。调整 `settings.json` 或根 `.env` 后重启生效。新增或升级平台源码后只构建对应输入镜像并重新组装统一镜像；Compose 结构保持不变。
