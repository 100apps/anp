# 目录与启动设计

三层是职责划分。存储和平台交付为一个工具镜像、一个容器；业务仍在宿主开发与调试。

```text
anp/
├── compose.yaml                   # 只启动发布镜像，不隐式构建
├── Makefile
├── AGENTS.md
├── .vscode/                       # F5、调试、准备与停止任务
├── docker/
│   ├── toolbox/Dockerfile         # 唯一构建入口，最终Debian slim
│   ├── toolbox/versions.lock.json # 组件版本、源码SHA、双架构下载校验
│   ├── toolbox/fetch.py           # 官方产物下载与严格校验
│   ├── toolbox/runtime/          # 配置、选服、独立UID、健康和退出管理
│   ├── build/                    # 生产构建快照及生成记录
│   └── licenses/                 # 官方许可与NOTICE
├── platform/sources/              # 真实submodule，仅源码定制时检出
├── business/
│   ├── pyproject.toml / uv.lock
│   ├── langgraph.json            # 图与内置HTTP扩展入口
│   ├── src/anp_business/         # Workflow、Deep Agents、平台路由与可选业务
│   └── ui/                       # React、shadcn、pnpm、Vite
├── scripts/                       # 操作、检查、验收和构建生成
├── tests/                         # Compose与运行时契约
├── docs/                          # 架构、配置、来源与验收证据
└── var/                           # 本工作区日志、缓存、导出和临时文件，不提交
```

## 镜像内部

主要程序安装在/opt/anp/bin，应用产物在/opt/anp/services，Node运行时在/opt/anp/runtimes，管理器在/opt/anp/runtime。为保留上游固定路径，PostgreSQL运行闭包使用/nix/store及profile，LiteLLM使用/app/.venv和/opt/prisma；这些都是镜像内的安装文件。

唯一持久映射为ANP_DATA_ROOT:/data。配置在/data/config，数据在/data/<service>，日志在/data/logs/<service>，状态在/data/run。保留已有布局，不因产品改名自动移动数据。effective目录由管理器生成，其余操作员配置不在重启时覆盖。

## 启动顺序

1. make init生成本工作区配置和随机凭据、工作区身份；make pull取得对应CPU架构的发布镜像。
2. make up按服务选择和依赖图启动进程，初始化独立存储目录，执行平台首次迁移，等待全部所选服务就绪。
3. make dev在宿主运行Vite和LangGraph Agent Server；业务扩展路由按/dbx、/langfuse、/litellm、/supabase代理工具容器。
4. 切换SERVICES会重建本工作区工具容器，保留同一个数据根；make down停止容器，make stop停止本工作区开发进程。

不运行Docker daemon、不映射Docker socket、不使用特权容器。服务使用独立UID，子进程只接收自身所需环境变量。启动管理器先停止平台，再停止存储。操作脚本校验容器的工作区身份，拒绝管理其它工作区的同名Compose实例。

## 构建与升级

make sources检出固定源码，make build执行单Dockerfile各阶段。优先官方二进制，没有可用独立发行物的组件生产编译后只复制运行产物。首次使用发布镜像不需要Rust、Go、Nix、平台源码或本机预编译组件镜像。

升级组件时固定新版本与源码，更新产物校验和配方，重建并验证双架构。新镜像经本地及CI验收后发布不可变SHA标签；数据库主版本、凭据和数据目录的迁移必须显式进行。
