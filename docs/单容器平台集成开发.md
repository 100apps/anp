## 构建与运行

先串行运行 `uv run python scripts/sync_upstreams.py` 更新上游并保存 SHA。之后各组件可以并行执行 `uv run python scripts/build_components.py --component <名称> --locked`。不允许并行修改 submodule 的 Git 状态。

组装器核对每个源码镜像的 revision label 与当前 submodule SHA，拒绝混用不同源码版本。缺组件只允许显式 `--partial`，只能使用开发标签；健康检查仍应失败。

当前包含 Agent 的隔离验收镜像命令：

```powershell
uv run python scripts/bundle_platform.py --tag anp/platform:agent-integration
uv run python scripts/configure_platform.py --public-url http://localhost:8089 --smoke
$env:ANP_PLATFORM_IMAGE='anp/platform:agent-integration'
$env:ANP_PLATFORM_PORT='8089'
$env:ANP_PLATFORM_STATE_VOLUME='anp_v3_smoke_platform_state'
$env:ANP_AGENT_STATE_VOLUME='anp_v3_smoke_agent_state'
docker compose -f deploy/platform/compose.yaml up -d
```

该示例连接隔离验收网络 `anp-storage_default`，不修改旧存储。8089 端口已有临时验证容器时，应先停止并移除本项目创建的该临时容器，不能同时争用端口。不得套用到含旧任务的 `anp2`。

私有运行配置由 `config/secrets.local.env` 生成，写入 `.local/generated/platform-v3/`；只读挂载具体文件，不能把整个 `/run/anp` 挂成只读，因为网关还需要生成私有 htpasswd。DBX 连接资料保存在平台状态卷，不覆盖用户额外添加的连接。

生成命令也会幂等更新 `config/local-credentials.md` 的 V3 专属段落，保留旧版信息。该文件和展开后的运行配置都不提交 Git。

## 存储 URL 与云资源

复制 `config/deployment.example.toml` 到忽略提交的 `config/deployment.local.toml`。使用以下命令生成私有配置：

```powershell
uv run python scripts/configure_platform.py --deployment config/deployment.local.toml --target container
```

`--target host` 选择同一文件中的宿主地址，供后续本机平台运行器使用；它本身不会启动或完成 F5。PG、Redis、ClickHouse、S3 的地址向消费组件和 DBX 同步传播；URL 中的密码需要按 URL 规范编码，可直接将完整云 URL 放入私有 env 后使用 `${CLOUD_PG_URL}` 等引用。

PostgreSQL 默认保留各服务独立账号与数据库，替换主机和 TLS 查询参数；托管服务的账号或数据库名不同，可在 `[postgres.urls]` 分别指定 auth、storage、postgrest、langfuse、litellm、agent 的 DSN。Meta 使用管理员 DSN。预先创建好数据库和账号时设置 `initialize_databases=false`；预建 S3 桶且不允许列举桶时设置 `initialize_buckets=false`。平台 SQL、上游迁移仍由对应阶段执行，不会因为关闭建库而省略。

Redis 支持 `rediss://`；ClickHouse 必须同时指定 HTTP(S) 查询 URL 和原生迁移 URL，不能根据一个 URL 猜测另一个端口。本机 Compose 的原生端口是 19000（服务内部为 9000），避免与 RustFS 的宿主 9000 冲突。S3 密钥、区域可单独配置。特殊服务参数可通过 `[services.<组件>.environment]` 覆盖。

资源绑定有独立测试验证服务账号、TLS、IPv6 和 DBX 参数传播；尚未连接真实云供应商，因此不能将配置测试称为云部署已验收。切换本地/云端不会自动复制或迁移数据库与对象文件。

## 运行方式与失败可见性

一个 Python 父进程管理平台子进程，Nginx 负责路径、WebSocket 与 SSE。进程退出最多退避重试五次；迁移失败、缺少制品、依赖超时会明确报告未就绪。迁移异常只记录类型，避免 DSN 泄漏。

不同上游运行时保留在 `/opt/anp/roots/<组件>`。部分组件通过 chroot 启动；Studio 和 Langfuse 的 Node 进程需要读取当前容器 `/proc`，使用可重定位运行方式。Langfuse 先在原根目录执行上游迁移，再通过原始动态加载器启动 Node，明确指向对应的 Prisma 查询引擎，保持上游 UID。没有嵌套 Docker、特权容器或额外 SYS_ADMIN 能力。

这种初版组装保留完整上游运行目录，镜像约 10.6 GB；这是已知待优化项，不能声称已经完成体积和性能调优。

## CI 导出层资源约束

正式流水线 39090955220 在 `exporting layers` 收到关闭信号、以 143 退出；交换空间最低仅 144 KiB。该证据没有直接确认内核 OOM，不将其当作已确定根因。

CI 现在启用 `scripts/bundle_platform.py --checkpoint-exports`：每个组件根目录形成一个命名构建阶段，依次导出到本次 UUID 的临时镜像标签，然后导出包含全部组件与 Agent 的最终镜像。这样尝试让已物化的层被后续缓存复用，减少最终集中生成大层的压力。检查点失败立即停止，最终标签不会更新；结束时仅移除本次创建的临时标签，不 prune 缓存或卷。部署仍只有一个平台容器，不运行检查点镜像。

本机需要同样策略时可显式加入该选项。完整 Linux CI 在正式组装前还执行 `scripts/verify_bundle_checkpoints.py` 的真实小型 Docker 对照。已验证文件内容、UID/GID、权限与软/硬链接语义；小型对照不能证明完整平台资源峰值或服务功能已通过，完整组装、服务和业务检查仍为发布门槛。

[Docker 官方并行度配置](https://docs.docker.com/build/buildkit/configure/)针对求解器；[BuildKit 层链物化实现](https://github.com/moby/buildkit/blob/master/cache/blobs.go)用于分析导出行为。分阶段策略仍需以实际运行结果验证，不能将求解器并行度配置等同于导出并发控制。

分阶段方案的完整 CI 现已完成导出与后续服务/业务检查并发布；仍观察到最终导出压力，详细采样和限制见 `docs/evidence/v3-ci-release-39095879677.json`。这不替代本机真实拉取、升级、模型调用及运行性能验收。
