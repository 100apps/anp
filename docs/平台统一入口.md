# 平台统一入口

工作台 `http://127.0.0.1:51760/workbench/` → Vite代理 → 本机 LangGraph Agent Server `20260` 的 HTTP 扩展 → 工具容器对应平台。无需Laravel，也不增加业务容器。生产静态工作台可用 `pnpm --dir business/ui build` 生成，HTTP扩展支持本地静态目录。

| 路径 | 宿主平台端口 | 容器端口 |
| --- | --- | --- |
| `/dbx/` | 54424 | 4224 |
| `/langfuse/` | 53400 | 3100 |
| `/litellm/` | 54400 | 4000 |
| `/supabase/` | 53401（Studio）、58400（API） | 3200、8000 |
| 存储PG / Redis | 57432 / 57379 | 5432 / 6379 |
| CH HTTP / Native | 59223 / 59400 | 8123 / 9000 |
| RustFS API / Console | 59402 / 59403 | 9002 / 9003 |
| 工具健康 | 57501 | 9750 |

HTTP扩展覆盖HTTP、WebSocket、流式响应、重定向、Cookie和压缩头契约。平台前端在生产编译时写入真实路径前缀；Studio额外修正其自托管API硬编码。Supabase Auth/REST/Storage由内部Envoy分流，外部仍共用`/supabase`。代理不会向浏览器输出服务密钥。

工作台可检测平台健康并显示不可用原因。仅选择部分服务时，其余路径显示503说明；这属于预期状态。全部服务启动后的页面、JS/CSS与API检查用 `make platform-check`，不能以代理契约测试代替实际平台验收。管理员凭据保存在工具数据目录，不在前端代码中。

Langfuse媒体签名链接区分内网上传地址9002和浏览器地址59402；线上可用 `ANP_S3_PUBLIC_URL` 指定对外S3地址。Studio读写连接明确使用postgres，另外配置只读角色，Studio/Meta共用派生的私有连接加密密钥。平台运维入口默认可信本机管理员使用。
