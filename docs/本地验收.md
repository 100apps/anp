## 处理过的实际问题

- Docker daemon 拉取 Redis 7.2 超时，显式选择本机已有且满足约束的官方 Redis 7.4.11，锁定实际摘要；没有静默使用 latest。
- Supabase PostgreSQL 配置目录必须保留镜像自带文件；初始化先复制缺失的上游配置，保留现有值，再绑定文件夹。
- Windows NTFS 下 ClickHouse MergeTree 目录重命名失败。数据改为 Docker Linux 主机上的 /var/lib/anp2-next/data 绑定目录，配置仍在 E:/anp2/var/config。此前新建的 Windows 测试目录保留。
- RustFS 以 10001 用户运行，使用一次性权限任务准备新数据目录，主服务保持非 root。
- Deep Agents 同步工厂中的版本探测会触发 ASGI 阻塞检查，改为在线程内构建图。
- Windows debugpy 路径探测同样触发 LangGraph 阻塞检测；只在显式调试模式使用官方 --allow-blocking，普通开发模式保持原检查。
- Vite 基础路径 /workbench/ 需要调试器 pathMapping；配置后前端断点绑定并命中。
- 官方生产镜像的 langgraph-storage-postgres 要求 psycopg<=3.3.3，已将本机/演示/生产统一为 3.3.3。API 元数据还要求安装匹配的 inmem 库；安装库不代表生产选择开发运行器。
- Windows 相对脚本路径导致 make stop 身份核验过严，已按 PID 创建时间、真实脚本绝对路径核验，并统一 Make 启动路径；不通过端口结束未知程序。

本机 Docker 构建网络存在 DNS/Registry 问题。本轮通过官方 Registry API 校验公开镜像摘要后导入，并使用仅监听回环、只允许公开包仓库的临时构建代理完成依赖准备；未重启 Docker Desktop 或修改其全局配置。后续普通缓存构建已通过。正常联网主机直接使用 Dockerfile 构建；首次下载仍需可用的 Docker 网络。
