# 配置参考

资源基线为8核16GiB。首次生成配置时CPU默认取Docker实际核心数与8的较小值，避免在4核机器上被Docker拒绝；已有ANP_CPU_THREADS值保持不变。CI使用runner实际核心数进行启动验收，不能把4核runner当成8核服务器。Docker不可用时配置生成暂按8核，启动前应确认Docker资源设置。

运行make init生成根.env和business/.env。配置是本机私有文件；示例只包含占位值。

## 工具容器

| 变量 | 默认 / 用途 |
| --- | --- |
| ANP_IMAGE | ghcr.io/100apps/anp:latest，可固定SHA标签或digest |
| ANP_SERVICES | all；支持storage、platform、langfuse、supabase和逗号分隔的单服务 |
| ANP_AUTO_DEPS | 1，自动启动本地依赖；0表示操作者自行配置完整外部依赖 |
| ANP_DATA_ROOT | Windows默认/var/lib/anp-next/data；其它系统默认工作区var/data |
| ANP_MEMORY_MB / ANP_CPU_THREADS | 16384 / 8，同时用于Compose资源约束和运行参数计算 |
| ANP_PUBLIC_URL | http://127.0.0.1:51760，平台回调和访问地址 |
| ANP_S3_PUBLIC_URL | 可选，浏览器可访问的S3媒体地址 |

make up默认选择all，make up SERVICES=...可临时覆盖。修改根.env后执行make up重新应用容器环境；修改/data/config文件后重启。发布部署显式设置独立数据根和访问入口。

默认端口仅绑定127.0.0.1：PG57432、Redis57379、ClickHouse HTTP59223/Native59400、RustFS API59402/Console59403、DBX54424、Langfuse53400、LiteLLM54400、Studio53401、SupabaseAPI58400、健康57501。对应变量为PG_PORT、REDIS_PORT、CH_PORT、CH_NATIVE_PORT、S3_API_PORT、S3_CONSOLE_PORT、DBX_PORT、LANGFUSE_PORT、LITELLM_PORT、STUDIO_PORT、SUPABASE_API_PORT、HEALTH_PORT。改映射端口后需同步business/.env的平台URL。

## 持久配置

/data/config/credentials.json首次生成，包含平台管理密码和服务密钥；只在自己的终端查看：

```sh
docker compose -p anp-next exec toolbox cat /data/config/credentials.json
```

POSTGRES_PASSWORD、REDIS_PASSWORD、CLICKHOUSE_PASSWORD、S3_SECRET_KEY和JWT_SECRET与已有凭据不一致时拒绝启动，必须显式轮换。不要靠删除凭据文件重置已有数据库。

/data/config/settings.json支持postgres_connections、postgres_work_mem_mb、log_max_mb、log_backups、memory_mb、cpu_threads；环境变量和实际cgroup内存约束优先于资源预算。派生的PG缓存、CH限额、Redis限额和Node堆写入effective/tuning.json。effective目录由管理器重写，修改它不能作为持久配置。

/data/config/services.json按服务名称覆盖平台环境变量，例如：

```json
{
  "litellm": {
    "DATABASE_URL": "postgresql://user:encoded-password@external-pg:5432/litellm",
    "OPENAI_API_KEY": "替换成私有Key"
  }
}
```

连接外部资源时先准备数据库和迁移权限，再设置ANP_AUTO_DEPS=0并选择要运行的服务。Supabase多个组件需分别配置连接；当前没有“一个PG URL自动改好整套Supabase”的入口。内部服务端口和健康探针固定，不应只覆盖PORT就期望管理器自动重配。

## 模型配置

/data/config/litellm.yaml配置模型和供应商，初始列表为空。供应商环境变量通过services.json的litellm条目注入，子进程不会继承根.env中的所有秘密。

业务使用LiteLLM时，在business/.env设置：

```dotenv
ANP_MODEL_MODE=openai
ANP_MODEL=在LiteLLM中配置的模型别名
ANP_MODEL_BASE_URL=http://127.0.0.1:54400/v1
ANP_MODEL_API_KEY=私有LiteLLM访问Key
```

ANP_MODEL_MODE=demo为默认离线演示。平台代理可用ANP_PLATFORM_DBX_URL、ANP_PLATFORM_LANGFUSE_URL、ANP_PLATFORM_LITELLM_URL、ANP_PLATFORM_SUPABASE_URL、ANP_PLATFORM_SUPABASE_API_URL覆盖；默认值见config/services/platform-proxy.env.example。
