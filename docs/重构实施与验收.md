# V3 重构与 deep_dub 的完整验收账本

本文件记录 2026-10-18 开始推进的完整目标。清单未全部有直接运行证据前，不称为交付完成。

## 完整范围与顺序

1. 存储只有 PostgreSQL、Redis、ClickHouse、RustFS 四类官方镜像；每类一个实例，也允许直接配置云地址/密钥。
2. 其余平台服务构建成一个镜像、运行在一个容器；第三方源码通过 Git submodule 依赖，发布构建先更新上游，记录实际 SHA。
3. 平台只暴露一个业务端口，Supabase、DBX、Langfuse、LiteLLM、Agent 和业务入口按路径访问；静态资源、API、重定向、Cookie、WebSocket 和 SSE 都要验收。
4. 平台支持 Docker 运行或 F5 源码调试；业务代码不打入平台镜像，始终在本机 F5 运行。
5. F5 提供“业务调试”和“业务+平台调试”两种：前者启动 Docker 存储+平台，后者只启动 Docker 存储。
6. 优化目录，更新 README、AGENTS；创建 GitHub 仓库并推送；GitHub 构建和发布默认平台镜像，验证实际可拉取、可启动及性能。
7. 上述平台验收通过后实现 deep_dub，工作台使用 shadcn/ui；数据库实体使用 deep_dub_ 前缀并明确关系、RLS、版本和状态约束。
8. 利用旧视频译配项目的任务验证新平台流程，每步记录实际输入/输出、耗时、设备和 Langfuse 分数。
9. 核实两块 GPU 和两个 CPU，基于实际运行数据优化；整片从排队/获取来源到最终验收的 RTF ≤ 0.5，不能用局部或缓存测速代替。
10. 完成对应 B 站发布及发布回执，不把“生成上传任务”当作上传完成。

## 已核实的迁移风险

- 现有 anp2 容器和 anp_v2_* 数据卷包含真实任务、登录、日志和文件；不能直接删除或同时让两个 PostgreSQL 进程挂同一数据卷。
- 最新 LiteLLM 源码是 1.107.0；现有运行版是 1.105.1。新版 Lens 已独立为 BerriAI/lens，不能复制旧版 Worker 配置冒充完成升级。
- 独立新版 Lens 使用 ClickHouse KeeperMap。Keeper 嵌入同一个 ClickHouse 服务，不额外增加第五个存储镜像。
- Windows 无法原生运行所有上游 Linux 服务；平台 F5 必须包含经过实测的 WSL 运行/调试适配，不能只写一个不会启动的 launch 配置。
- “最新依赖”可能改变构建和数据迁移；失败时停下适配，不能静默退回旧镜像却标记为最新。
- 把服务放入一个容器不会自动降低它们的总内存或提升吞吐；性能结论必须给出实测负载、硬件与参数。
